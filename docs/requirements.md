# Вимоги до проєкту Vacancy
 
## 1. Призначення
Веб-застосунок для перегляду каталогу вакансій роботи
та відправки їм резюме, або для створення вакансій .
 
## 2. Ролі користувачів
- Відвідувач — перегляд, пошук, фільтрація, створення резюме, надання резюме, створення вакансій.
- Хелпер — всі више перечислені можливості, блокування облікових записів, видалення вакансій.
 
## 3. Сутності предметної області
| Сутність  | Атрибути                                            |
|-----------|-----------------------------------------------------|
| User      | id, name, email, password, role                     |
| Vacancy   | id, author_id, title, description, salary, status   |
| Resume    | id, user_id, skills, experience, contact_info       |
|Application| id, vacancy_id, resume_id, status, created_at       |
 
## 4. Зв’язки
User 1 — ∞ Vacancy
User 1 — 1 Resume
Vacancy 1 — ∞ Application
 
## 5. Сторінки
1. `/`            головна: панель з пошуком та фільтрами, посилання на профіль, лого сайту, вакансії
2. `/vacancy/:id` детальна сторінка вакансії, для автора буде конпка редагування та для автора разом з хелпером кнопка видалення вакансії
3. `/profile`     особистий кабінет користувача для самого користувача, де він керує власним резюме, переглядає збережені вакансії або створює власні пропозиції роботи.
4. `/user/:id`    публічна сторінка користувача. Відображає загальну інформацію про автора .Для Хелпера: на цій сторінці з'являється кнопка "Заблокувати обліковий запис".

## 6. Функціональні вимоги
F1. Дані завантажуються асинхронно з сервера.
F2. Фільтрація не перезавантажує сторінку.
F3. Форма створення вакансії перевіряє заповненість усіх обов'язкових полів.
 
## 7. Нефункціональні вимоги
N1. Адаптивність від 360 px.
N2. Lighthouse Performance ≥ 85.
